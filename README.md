# Engineering Gravity — 可泛化的工程经验

> These aren't best practices. They're gravity —
> the same failure patterns, independently reproduced in two unrelated codebases.

约 320 条工程经验, 全部来自真实踩坑, 逐条可追溯到 commit。来源是两个技术栈与业务域完全不同的项目, 各自的 commit 历史被**全文逐条阅读**后提炼:

- **项目 A** — 实验室信息管理系统 (LIMS): 210 万行 VB.NET WinForms 桌面系统向 TypeScript 全栈 (React/antd + Hono + PostgreSQL) 的 Web 移植。868 条 commit, 另加 40+ 份工作记忆与设计约定沉淀。
- **项目 B** — 跨境批发电商 storefront 后台 (Next.js / Shopify / Prisma / Playwright)。1322 条 commit。

收录标准: **能脱离原项目泛化**的经验才收, 项目特定业务事实不收。
括号内为 commit 短哈希 — 无前缀为项目 A, `B xxx` 为项目 B (源仓库私有, 哈希仅作溯源锚点)。
整理日期 2026-09-15。

两个互不相关的项目独立踩出同一批坑 — 这不是巧合, 是工程重力。

## 1. UIUX / 交互

### 1.1 保存与反馈

- 保存模式按场景定型、全站统一: 密集网格用内联失焦自动存, 普通编辑用「草稿 + 显式保存按钮」, 单记录用弹窗保存。用户实测偏好显式保存 — 失焦自动存让人困惑"怎么保存"、toast 刷屏、DB 写入频繁。
- 保存必须有反馈 (防抖 + key 去重的 toast); 失败必须可见 — handler 一律 try/catch + 报错, Modal 提交失败 rethrow 保持弹窗打开 (`20813e6`)。
- 「按了没反应」的病根是校验错和 API 错一个 catch 全吞 → 分层: 校验错标红留弹窗 / API 错报服务端原因 / 前置条件不满足在弹窗顶部 Alert 直告, 别让用户白填 (`dcec6dd`)。
- **表单字段 ↔ 提交 payload 的映射漂移是无声丢数据的高发点**: 表单收集了字段但 payload 从未发送 (`f6231e4`); 新增字段核对"收集了 = 发送了 = 落库了"三段。
- 残留默认值 (改字段类型后 initialValues 没清) 会让 create 静默失败, 表现为"按钮点了没反应" (`b3fa04d`/`b3d4da7` 家族, 见 `b3d…`≈`b3d4`; 原例 `b3d`→`b3d4da7`) (`b3d4da7`)。
- HTTP 错误层要透传服务端业务错误文案 — 只显 "HTTP 400" 用户不知被哪条校验拦 (`63ff837`)。
- 拦截性提示必须可操作: 写明下一步动作 ("先保存再加下一级"), 不是只说"不行" (`3fcaaf6`)。
- 可静态判断的前置条件 (列表为空/未选择) → 按钮直接 disabled + title 说明原因, 不做"点了才弹警告"; 运行时才知道的校验保持 message.warning/error。
- 保存按钮做脏状态门控: 无未保存改动时禁用, 兼作"有没有改动"的即时反馈 (`60f6f91`)。
- 批量操作的失败反馈按理由分组汇总 ("0 件添加、2 件失败: 原因×N件"), 错误 toast 比成功 toast 显示更久 (B `9282b74`)。
- 切换类操作要消费 isPending 给反馈 — useTransition 的 isPending 拿了不用, 用户感觉"卡死" (B `71ae24c`); loading 的解除一律放 try/finally, 失败路径漏解除 = 永久转圈 (B `3607075`)。
- 乐观更新必须配失败回滚 (B `077ebc0`); 乐观删除的"回收"时机 = 新服务端数据真正到达时 (useEffect 监听 props), 紧跟 router.refresh() 就清会闪回旧数据 (B `0b93d5a`)。

### 1.2 数据呈现的诚实性

- **假数据比缺数据更害人**: "报告类型 = id%4"、恒为'—'的列、硬编码空串、mock 假统计数字 (`294f7f2`) — 界面看着有数其实是编的。对照走查时先怀疑派生表达式。
- 「共 N 条」计数与 CSV 导出必须绑定筛选后行集 (shownRows), 不是全量数据 (`4f2df35`); 状态 Tab 上的计数同理基于已过滤集 (B `99780b1`)。
- 统计卡口径纪律: 卡片数字 = 点进目标页后默认视图的条数, 且链接指对页面; 口径用测试两端对账 (`723e6a1`)。
- 聚合/摘要文本必须忠实区分 空/全量/子集 三态 — "无参数"写成"所有参数"用户点开就懵 (`921a22b`)。
- 数据黑洞审计: 每个写入口必须有对应的展示出口, 否则用户填了就消失 (`6b82402`)。
- 老系统靠 inner join 静默吞掉的断链行, 移植时改 leftJoin 如实显示 + 空显 '—' — 数据问题要可见, 不是继续隐藏 (`c4473e6`)。
- 未移植功能挂诚实占位页 (功能名+出处+说明); 假筛选器要么置灰要么删 — 死控件是在骗用户 (`2eb4486`)。
- 正式输出物 (报告/单据) 上的机构名等法务信息绝不硬编码占位; 查不到真值就做配置位 + 未配置告警, 不猜测替换 (`c3fa883`)。
- 有点击行为的单元格空值给动词文案 (如「勾选参数」), 裸 '—' 无按钮感。
- 用户可见的假标识是"骗用户": ID 体系断裂时显示 "#N" 比 "—" 更糟; 止血改语义占位, 治本走写时冗余 (`2329d3a`)。
- **同一实体的列表与详情必须同源同规则取数** — 列表用 priceRange 显 ¥0 而详情用 variant 实价、列表只看上游状态而详情优先物流 API, 两处矛盾必然被用户抓到; 统一到同一数据源 + 同一优先级规则 (B `591c7dc`, `2aebc77`)。
- 上游枚举做穷举映射 + 未知值兜底 — 漏映射一个 VOIDED 就把已取消订单显示成"待支付" (B `944d353`)。
- 金额标签的含税/未税口径要实证 API 实际返回值, 别按业界惯例写"合计(税込)" (B `043074f`)。
- 排行/榜单类 UI 对已下架实体灰显 + 徽章, 而非过滤消失 — 过滤会导致条数不足; 取数要超采再截断 (B `1ebd748`, `8d3f5b3`)。
- "曾存在但已下架"与"根本不存在"给不同页面: 已知非公开实体显示问询引导页, 未知 id 才硬 404 (B `8f6b217`)。

### 1.3 状态与加载

- 列表 Table 必须有 loading (慢网下"暂无数据"误导为空); 详情页三态 (加载中/未找到/有数据), 双态会闪"未找到"首帧 (`86f3278`, `cb1cf39`)。
- 只读/锁定态渲染纯文本, 不用 disabled 控件 — disabled 吞点击, 连"选中行"都点不了 (`bbd96e4`)。
- 状态词表全站单源 (同状态同词同色); 前后端共用的 label 映射放共享包, 手工副本必然漂移 (`f4dc524`)。
- 状态驱动的按钮显隐全站同口径, 一处裁决记为先例 (发放按钮仅已签发显示 `d63450b`)。
- 行内按钮按状态隐藏会跳位 → disabled + tooltip 说明原因, 终态也保留 disabled 占位; 只有权限性隐藏和查看类导航例外。
- 弹窗先开后取数: 点击立即弹出 + Skeleton, 取数完成再换内容; `await fetch` 完才 `setOpen(true)` 像卡死。校验/写库类 await 前置才合法。
- 弹层内自成保存域的控件不绑页面编辑态 — 否则按钮在只读态"神秘消失"。
- **加载中 ≠ 零值**: 状态未取到时把实体当"无状态"会开放不该开放的动作 (报告勾选), 动作许可要等 loaded 标志; undefined(加载中) 与 null(无数据) 分态显示 (B `e85ac25`, `4dacdf6`)。
- 非核心增强数据源 (外部 API) 失败要局部降级出错误提示, 不能 SSR 整页崩; 错误态 (null) 与空态 ([]) 分开表达 (B `a9f325f`, `99d6877`)。
- error / empty / no-result 三态收敛成单一共享组件, 各页手搓必然文案与形态漂移 (B `ae68bd2`)。
- 数据为空时连带隐藏依附它的控件 (排序器/筛选器), 别留一排操作空集的死控件 (B `d51c432`)。
- 异步刷新先清 stale 数据, 失败时也置空 — 旧数据与 loading/error 并存会误读; 删除动画等过渡态在新数据到达前不复位, 提前复位会闪回重放 (B `cbadf66`, `60abfdf`)。
- "加载更多"的可见条数在排序/过滤切换时要重置, 配 NaN 守卫 + 稳定 tiebreaker, 否则切换后列表长度与顺序都不可预测 (B `01ab9a2`)。

### 1.4 导航与 URL

- 跨页往返的上下文进 URL 参数 (?task=、?tab=), 页内 state 一回跳就丢; tab↔URL 同步让刷新/分享/回退不丢位置 (`3934e02`, `abaa3ea`)。
- 路由重组给旧路径全量 redirect — Never break userspace 同样适用于前端路由; 未知路由重定向而非静默渲染首页 (`4c9e0ad`, `68284d8`)。
- 菜单高亮用最长前缀匹配, 匹配不到禁止 fallback 高亮第一项 (`bef191f`); 菜单 1:1 镜像实际页面, 不为未来功能预留 (`dd24ec3`)。
- 深链/快捷入口必须指向注册的真实路由, 落 catch-all 会变成"无过滤"页面 (`c3fa883`)。
- 侧栏展开态随 pathname 自动补展开 (只开不收), 不与手动开合打架 (`8982414`)。
- 面包屑等 path→label 映射从菜单配置推导, 不手工维护副本 — 两处维护同一份映射迟早漂移。
- 未保存守卫要拦在最底层公共 API: monkey-patch history.pushState/replaceState + beforeunload + popstate + 标题前缀四层兜底; 拦 UI 入口 (useBlocker/拦 `<a>` click) 都会漏 (`a9fcde8`)。异步确认框不能同步阻断导航: 先同步 return 阻断, 再弹应用内 Modal, onOk 置 bypass 标志重放导航 (`454044a`)。合成事件与真实用户事件用 `e.isTrusted` 区分, 防守卫双弹 (`9a1e168`)。
- 菜单默认焦点跟随当前页面上下文 (从 pathname 推导), 不固定第一项 (B `4491e61`)。
- "导航即回顶"只绑 pathname 不绑 searchParams — 页内 tab/参数变化不是页面迁移, 否则每切 tab 被拽回顶; 散落各 layout 的 scroll reset 收敛为全局单组件; 全局 `scroll-behavior: smooth` 会劫持路由回顶变成慢动作, 慎设全局 (B `3006737`, `95e7637`, `639d48d`)。
- URL 体系迁移 (数值 id → handle) 三件套: 全部链接生成点统一改 + 旧 URL 自动 redirect 兼容 + 分散入口 (通知卡片等) 单独排查漏改 (B `3a4b28e`, `0083f62`)。
- 旧 ID 兼容分支遇到纯数字形态的自然键会自我重定向死循环 — redirect 前先判「解析结果 ≠ 当前路径」 (B `95cf033`)。
- 分组导航 (A-Z/假名索引) 必须有 catch-all「其他」组 — 数字/符号开头的条目不匹配任何分组就静默消失 (B `9a9caa3`)。

### 1.5 表格

- 移植表格先抄老 grid 完整列清单, 逐列显式裁决 (对应/合并/裁掉+理由) 并打勾验收 — 按新数据模型正推"该显示什么"必漏列。
- 操作列统一走共享组件 (RowActions); 编辑态才渲染整列, 只读态不留空占位; 表级工具按钮放 section/Card header 标准尺寸, 子组件经 ref 暴露动作反调。
- 编辑模式 = 全表直编 + 草稿**懒播种** (首次改动以整行现值为底, 防部分 patch 冲掉未动字段)。
- 主从联动 = 焦点行语义 (点行即选中过滤, 不 toggle, ✕ 清除); 并立不变式「选中行不在行集则自动清选中」— tempID 保存换 realID 后按幽灵 id 过滤成空表 (`d3f8932`)。
- 日期列宽基线 (编辑态 date ≥140 / datetime ≥175; 只读 ≥110/≥150); 定宽+nowrap 必须带 ellipsis+title; 多值长文本列收起单行 (前 1-2 项 + 等N项 Tag + Tooltip)。
- 列宽按"最长状态文案"预留 — 状态词变长会挤爆列。
- 全局表头 nowrap 通杀 CJK 短标题竖排"单字塔" (`eac48fa`)。
- 有横向滚动的表格: 操作列 fixed:right + 行标识列 fixed:left (`8376e91`)。
- 行点击详情做全站一致性 sweep, 且只加不发明 (无详情概念的表不硬造); 行内链接/开关 stopPropagation 防与行 onClick 双触发 (`530ce94`, `4211b05`)。
- 可增删列表 rowKey 用稳定键不用 index, 删行不串显 (`77e975c`)。
- 大行数 × 行内控件表格开虚拟滚动 (`0fda257`)。
- 业务排序中 NULL 的位置按业务语义定 ("无计划"沉底, 首屏留给最紧迫) (`02fd55c`)。
- 表格宽度无限自增是双因叠加: 测量行被全局 padding 命中 + grid `1fr` 可被内容撑开; 修法 measure-row 归零 padding + `minmax(0,nfr)` (`8743a09`)。
- 全局截断 (slice top-N) 必须在过滤**之后** — 过滤前截断让特定分类的条目被挤出, 两个页面同数据源条数打架 (B `242a71a`)。
- 去重 key 的粒度 = 展示粒度的唯一键 — 用 productId 去重会把同品不同 variant 滤掉 (B `0f2ce93`)。
- 列表默认筛选对准用户最高频诉求 (默认"未支付"而非"全部") (B `b56695c`)。
- 列表页别为每行预取慢速外部 API (行数×秒级), 改详情打开时按需取 1 件, 列表用既有粗粒度字段渐进显示 (B `3b7e8aa`, `2aebc77`)。

### 1.6 表单与控件

- 「依赖保存」反模式: 联动过滤/候选下拉/弹层取数必须对**未保存草稿**即时生效 — 任何"从行数据取值驱动 UI"的地方, 行数据必须是草稿合并后的。
- 上下文字典别倒全量: 挂在配对/父实体上的字典下拉必须按行上下文过滤 — 倒全量 = 同名重复 + 能选到别家的数据。
- 派生/受控字段用字典 Select 不用自由文本 — 值参与下游过滤链时错一个字整条链断。
- 选项多的下拉全站默认可搜索 (`a5fa11f`)。
- 格式约束用拦截式输入 (onInput 就地清洗/键入拦截), 不做提交时报错; 可能含定性值 (ND、<0.05) 的数值列保持文本口径别上 InputNumber (`1c8fcc1`, `bbd96e4`)。
- 数量/金额类输入框要处理 IME: composition 事件 + NFKC 全角数字归一 + string state 允许清空 + focus 全选; 数值键盘给 `inputMode="numeric"` — 同一修复几周后在另一处 (购物车) 重打一遍, 再证"修 bug 先全局 grep 同类" (B `9cc999a`, `e1a0d98`, `1571889`)。
- 用户手填的多值字段解析要宽容: 半/全角空格、换行、读点、逗号全当分隔符, 运营不必记格式 (B `6c8b302`)。
- 步进控件的上限判定用「当前值+步长 > 上限」而非「当前 = 上限」, 且到顶必须显式告知原因 — 该判定前后修了 4 次, 教训是判定式越直白越好 (B `c7dbea7`, `fbb539f`)。
- 数量倍数/最小/最大类约束在**所有**数量入口 (详情加购/购物车±/直接输入) 统一执行, 收敛共享校验函数 (B `6352979`)。
- 搜索框按输入形态自动路由检索类型 (13 位纯数字→条码检索), 省掉用户手选 (B `961590a`)。
- form 内非提交按钮显式 `type="button"` — 默认 submit 会连带触发整表提交 (B `a3a143c`)。

### 1.7 文案与视觉

- UI 单语言, 不搞"中文 (English)"双语并列 — 多语言走 i18n; 双语并列是开发者注释习惯, 对业务用户是噪音。
- 界面禁开发对照口吻 (老系统名/表名/SP 名) 与内部 id; fallback 用业务编号; 不许出现"(后续支持XX)"类未来承诺 (`3fc22a2`)。
- 术语对齐老系统词表, 老用户见词识面; 用户反复问同一控件的用途 = 文案缺陷信号, 改成自解释而不是口头解释 (`c8fc629`)。
- 全局模式开关太安静会忘切: 当前模式多点回显 (placeholder/彩色 Tag/行级列) (`6fcf09b`)。
- 一屏只有一个 primary; 流程按钮按状态机分主次, 非当前步 default+disabled+Tooltip 指路 (`2b5e019`, `c779ae0`)。
- 尺寸/间距基线走全局 CSS, 组件里不用内联样式对抗; 但全局规则会误伤意外目标 (首列留白挤出 checkbox), 要配套豁免机制。
- 状态色永远跟语义走, 禁止按位置配色 (nth-child 上色)。
- 待办与聚合统计去重、各司其职: 聚合计数归趋势视图, 待办只留带具体项+截止日+一键动作的条目 (`fb0391d`)。
- 反直觉但正确的事实在注释写明"别再顺手纠正回去" (`89a48d7`)。
- 价格等关键数值不用徽章/填充样式, 防与促销标混淆; 非交互徽章要与按钮形态区分 (pointer-events:none, 描边 vs 填充分家), 否则被当按钮点 (B `71cae4a`, `efbd30f`, `b165eea`)。
- 货币符号+数值+附属图标 (锁) 整体 nowrap, 防中途折行 (B `e3c0782`)。
- 叠加在任意图片上的控件 (轮播指示点) 用 border+阴影双保险, 不能只靠半透明色 — 底图颜色不可控 (B `aa9e22b`)。
- 大爆炸式视觉刷新必被整体 revert — 存活的改法是「不动布局、只动视觉、无 !important、小步提交」; 高感知元素 (CTA 配色) 更要小步 (B `39d32f2`→`db1211d` 及两次同类 revert, `3f308e1`)。
- 内容防转载: 登录者身份 SVG 平铺全屏水印 + pointer-events:none + 低透明度 — 不碍操作且可追溯泄源 (B `a6f0f00`)。
- 别用 CSS text-transform 强制变换品牌/人名大小写 — 展示层擅自改写数据 (B `49fa974`)。

### 1.8 面向用户的判断

- 用户画像决定 UI 密度: 自作主张改 icon-only 被年长非 IT 用户否决, 32 处改回 icon+文字 — 别做无输入的美学优化 (`afefbab`)。
- 老 UI 的醒目 affordance 要等价复刻 (整块变色的激活态 → Radio solid 大按钮, 安静的 Segmented 会被指出)。
- 不因新模型细分而增加操作入口 — 老用户的肌肉记忆优先, 细分动作走低频入口。
- 物理上不成立的需求果断放弃: tab 滚动位置记忆三版补丁全败, 收敛为业界默认"切 tab 回顶" — 确定性 > 聪明补丁 (`4ab2ab1`)。同族: 无限循环 marquee 与手动交互天然冲突, 五版演进 (CSS animation→rAF→scrollLeft→子像素补正) 最终收敛为「有限滚动+末尾静止回卷」的简单模型; 手搓 Lottie 类复杂动画必败, 快速回退 (B `e0df6ae`, `0428456`)。
- 上线前用可点击 HTML 线框 + 真实埋点 + 引导 tour 跑用户访谈, 用行为数据驱动砍功能 — 比开完再改便宜一个量级 (B `ffc8d2b`, `3d781d2`)。

### 1.9 细节坑

- window.open 必须在用户手势同步期预开, await 之后再开会被弹窗拦截器拦掉 (`125a8b7`)。
- 动态生成的打印/弹出 HTML 显式 lang (+字体链) — 无 lang 时 CJK 按系统语言选字体, 异语言系统下部分字形静默空掉 (`5a2b3d7`)。
- 装饰性元素 (条码) 编码失败不能白屏整张单据; 用户自由输入喂编码库要设防字符集 (CODE128 只编 ASCII); 打印到物理介质的条码内容用稳定业务标识, 不用内部数字 id (`4211b05`, `8e579b5`)。
- 图表参考线 (控制限 UCL/LCL) 必须并入坐标轴 domain 计算, 否则被自动范围裁掉静默不可见 (`33944fa`)。
- sticky top:0 在带 padding-top 的滚动容器里只贴 padding 内边, 内容从吸顶栏上方透出; 吸顶体系收敛成统一 CSS 类 (`365770b`)。
- 列表内媒体预览懒加载: 点击才拉 blob, 别渲染时并发拉一排 (`de24baf`)。
- 弹窗多 tab 默认落在有数据的 tab, 空态给引导链接 (`bfbe2d1`)。
- CSS tooltip 在 overflow/stacking context 复杂容器里是 z-index 打地鼠, 原生 title 渲染在 DOM 外天然免疫, 果断回退 (B `6a4879c`)。
- 复杂菜单悬停态用显式 state, 纯 `:hover` 会在 padding 死区丢选中并被 default-active 抢走; 悬停菜单加 ~200ms 关闭延迟且保留点击打开 (B `1e18a7a`, `e7cb241`)。
- max-height 动画是隐性截断炸弹: 条件挂载让 transition 从未运行, 只剩 `max-height + overflow:hidden` 的裁剪副作用, 超长内容尾部被静默切掉 (B `64ce5af`)。
- 网格"间隔太宽"的病根常是固定列数/百分比宽超出卡片 max-width 形成死空间 — 先改 `repeat(auto-fill, minmax())` 列宽模型再调 gap (B `be38fb8`)。
- 轮播闪烁的根治: 全 slides 绝对定位常驻、只过渡 opacity, 别挂载/卸载切换 (B `a68e44f`); 滚动轨道只在实测内容溢出时才复制卡片/启动动画, 无条件复制在不溢出时复制品直接可见 (B `396dd74`)。
- 嵌在卡片里的弹窗 outside-click 关闭会失效, 用 createPortal 挂 body (B `6d92297`)。
- JSX `{n && <X/>}` 在 n=0 时渲染字面 0, 用三元或 `n > 0 &&`; `str.includes('')` 恒真, 过滤条件空串要先短路 (B `f4a6ab7`, `7d996cb`)。

## 2. 前端工程 (React / antd / Next.js)

### 2.1 表单陷阱清单 (antd v5/v6, 写新代码先对照)

- `destroyOnHidden` Modal/Drawer: 打开前 `setFieldsValue` 写进未挂载实例全丢 → 正解 `key={editing?.id ?? 'new'}` + `initialValues=`; 纯新增默认值也搬 initialValues (可引用作用域 state 动态计算) (`b0746c7`)。检测配方: startEdit 里 setFieldsValue + destroyOnHidden + 无 key/initialValues = 坏。
- `Form.useWatch` 默认只通知已注册字段 — 无 Form.Item 的字段要 `{ form, preserve: true }`。
- `form.getFieldsValue()` 不含未注册字段 — 保存时单独 `getFieldValue`。
- 非受控 `defaultValue` Input 不随数据刷新 — 加 `key={value}` 强制重挂载。
- Modal/Drawer 表单分 tab 要 forceRender — 未渲染 tab 的字段不进提交, 静默丢字段 (`786dd67`)。
- Table pagination 用 `defaultPageSize` 不用受控 `pageSize` (会把用户每页条数改回去)。
- showSearch Select 若 value 是数字 id 必须 `optionFilterProp="label"` — 默认按 value 过滤, 输文字全滤空 (`a505791`); filterOption 按当前已选值过滤会"下拉打不开", onSearch 仅键入时过滤 (`ef8239b`)。

### 2.2 状态与数据流

- null vs undefined 双坑: 草稿"清空"必须用 null (JSON.stringify 丢 undefined, 清空不落库); 受控 Select 清空设 null, undefined 让组件转非受控残显旧值 (`d68b5b2`, `8b87cc8`)。
- 防重复提交用 ref 同步守卫 (useSubmitLock), 单靠 loading state 不够 — setState 异步有竞态窗口, 卡顿时双击建两条 (`a7bf1a0`)。
- 草稿 tempID 计数器用 useRef 不用 state — 渲染闭包读旧值, 同帧连点拿相同 id 互相覆盖 (`bd8f907`)。
- 草稿行互引用用负 id 占位, 提交时统一 idMap 换真 id (含新行之间互引); 单条坏草稿降级跳过+告警, throw 且草稿不清 = 每次保存都失败的永久卡死 (`a135643`, `76807a2`)。
- "添加"用本地草稿行, 不先 create 空服务端行 — 取消就留孤儿脏行 (`9abd8bf`)。
- M2M 关联仅用户 touched 才 PUT — 表单初始化期的空值会把库里数据误清空。
- react-query 缓存失效三型缺口全查: invalidate key 与列表 key 失配 (不刷新)、兄弟组件的 key 无人失效 (弹窗看不到新数据)、父级派生计数不连带; 发现一处做全站同型审计 (`d3f8932`, `0056563`); 变更后连带字典/候选缓存 (`db24903`)。
- render 阶段 setState / 把 useState initializer 当副作用用是 React #310 崩溃源, 改 useEffect + ref (B `4b33b46`, `d666e2d`)。
- 时间派生值 (剩余天数等) 不用空依赖 useMemo 缓存 — 页面常开就过期 (B `539681b`)。
- React Compiler 时代手写 useCallback 反而破坏自动 memo ("Existing memoization could not be preserved") — helper 提出组件外做普通函数; set-state-in-effect 类新 lint 的正解是逻辑进 useState 初始化函数 / hydration 判定用 useSyncExternalStore, 不是 suppress (B `d99a31f`, `03bf478`, `cedde84`, `faaca63`)。
- 互斥 props 用 discriminated union 建模, 让非法组合编译期报错 (B `b3b2d80`)。
- 空结果返回用工厂函数, 不共享可变常量 — 共享的 `EMPTY = []` 被一处 push 全站遭殃 (B `d54ebe9`)。
- 字段正规化 (metafield 优先→raw fallback 之类) 收敛到唯一 transform 层 — 逐 query 手抄必漏一处独显原始值; 多别名逐字段取数改批量 identifiers 接口并删除映射数组, 消除二重管理 (B `b400946`, `49fa974`)。

### 2.3 样式与可访问性

- 自定义主题覆盖控件样式必须连全部状态 (:disabled 等) 一起覆盖, 漏一态 = 全站系统性视觉 bug (`a62691f`)。
- `<div onClick>` 是键盘死区 → 抽共用 kbd() helper (role=button + tabIndex + Enter/Space) + `:focus-visible` 焦点环; 有 cursor:pointer+hover 却无 onClick 同样是误导 (`62429c9`)。
- 硬编码色 token 化只换与 token 值精确相等的语义色, 图表系列色/装饰色保留 (`73f1a6a`); CSS 变量名拼错不报错只走 fallback, 纳入 audit (`98f8045`); 内联 hex 是 token 演进时的漂移源 (`2942692`)。
- a11y 系统性修法: axe 走查 + token 同源加深 + 违规计数清零式推进 (`d23d297`)。
- backdrop-filter/transform 会创建隐式 stacking context 令子元素 z-index 静默失效 — 给容器显式 position+z-index; overlay 的 z-index 要压过固定底部导航, 且 overflow:hidden 会盖掉内部 overflow-y:auto (B `0321857`, `d60fe73`)。
- Tailwind Preflight 会把富文本 HTML (CMS/博客 contentHtml) 重置成平文 — 配 prose 样式层, 且 h4-h6 也要覆盖 (粘贴内容常生成 h4) (B `06eedda`, `b498c42`)。
- 跨仓移植 UI 带着源项目的样式类, 目标项目构建时类不存在**不报错只静默裸奔** (白底白字按钮不可见) — 移植必须转译到目标设计体系 (B `6f70fd2`, `d176ff1`)。
- 移动端适配清单: 触屏断点关 hover transform / 触target ≥44px / iOS safe-area / 浮动元素避让底部导航 / 未设断点的 grid 逐个补护 (B `f3290d0`, `9f4cf67`)。
- 响应式只有手机/桌面两档必在平板带 (768–1024) 崩坏 — CJK min-content 撑爆分数列致 aspect-ratio 破绽, 补中间断点; flex/grid 的 min-content 约束链每一层都要 min-height:0 / minmax(0,), 漏一层照样撑破 (B `19c4dda`, `216e1b7`, `6d832b2`)。
- 移动抽屉 a11y 套路: focus-trap + aria-modal + Escape 关闭, 做成共享组件 (B `7e00246`)。

### 2.4 性能

- 性能配方 (React 审查一轮沉淀 `bf4bf0b`): useFormDirty 替代 `Form.useWatch([])` 整表订阅; 重库 (exceljs/html2pdf/jsbarcode) 动态 import 出首屏; react-query 4xx 不重试 (坏链接 7s→120ms); invalidate 按域精确; 密集文本格改 defaultValue+onBlur+key; >100 行开虚拟表格。
- 高频键入别触发全页重渲: 草稿态收在局部, commit 时才上提。
- router 把导航包进 transition 后旧页保持渲染 (v7), 慢网点菜单似死机 — 自建"chunk 在途"信号出骨架; 自建并发通知要处理"后归零者无人等待"死锁 (`2f43c96`)。
- 首屏性能三件套: 取数 Promise.all 并列 + loading.tsx 骨架 + LCP 图 priority+sizes; below-the-fold 用 Suspense 边界切成流式渲染, 首屏阻塞 API 数收敛 (B `aef96df`, `0eab584`, `c4c9e02`)。
- 动态页面的慢速外部 API 解析按可视窗口懒执行: 首屏 N 条 + Server Action 按需 + in-flight 去重 + 解析失败负缓存, 否则成本随数据量线性涨 (B `d61d635`)。

### 2.5 工程纪律

- **自查命令与 build 同严格度**: Vite dev 松、tsc 严, "dev 绿 build 挂"一周绊 4 次 (`526d2a2`); solution-style tsconfig 下 `tsc -p .` 静默检查 0 个文件永远 exit 0 — 校验工具本身要先被校验。
- `as never` 等类型断言压掉的报错是定时炸弹; "本地能跑"可能只是数据巧合 (PK 无默认值本地没炸只因行已存在, 全新库必炸) (`a3b29e3`)。
- 路由注册顺序遮蔽: 通用 `/:id/:action` 把后注册的具体路由吃成 no-op 且无报错, 具体路由先挂 (`d5636fb`)。
- 前后端接口走共享 types 包防 schema drift; create 返回值解构并类型化 — `{id}` 被当 number 拼出 `/detail/[object Object]` (`0334a4c`, `87cc223`)。
- 块注释内容里不能出现 `*/` 字符序列 (JSDoc 写通配模式截断注释) (`ac50106`)。
- 给公共组件加特殊 case 会污染所有既有用例, 形态差异大时宁另立新组件 (B `efae34a`)。
- HTTP 客户端迁移 (axios→fetch) 时超时/重试等隐性配置会丢, 逐项核对 (B `b5affcd`)。
- CLI/批处理脚本与应用共仓时给独立 tsconfig (CommonJS + 相对路径), 跑编译后的 dist, 别蹭应用的 bundler 语义 (B `8d57e54`)。
- i18n 后置引入选 Cookie/请求级 locale 注入, 不动 URL 结构 — 既存路由零破坏; 翻译键放错 namespace 只在另一语言运行时爆 MISSING_MESSAGE, 多语言文件对称性要机器校验 (B `2da7af2`, `2d383bb`, `00fbdb8`)。
- 死掉的 lint pragma 也是债 — 项目已换 ESLint 却残留 biome-ignore, 无效抑制注释随手清 (B `ffb2eda`)。

### 2.6 SSR / 构建与缓存 (Next.js 类框架, 均项目 B)

- 部署后用户浏览器还跑旧 JS: generateBuildId 绑 commit hash + 静态资源 Cache-Control 策略配套 (B `df3f22e`)。
- SSG/ISR 页面构建期上游取到空数据会把空态**永久缓存** — 数据驱动页面显式声明缓存策略 (force-dynamic/revalidate); "首页没事"可能只是它恰好 force-dynamic (B `c42adbd`, `79e8b81`)。
- 外部资源 slug (博客 handle 等) 是环境相关配置, 换环境上游 API 静默返 null 而非报错 (B `fe9baf2`, `13a204a`)。
- 框架用异常做控制流 (Next.js redirect() throw NEXT_REDIRECT): 宽 try/catch 会吞掉跳转, session 过期静默不跳登录 — 认证/redirect 放 try 外, 只 catch 数据调用段, 或识别后 rethrow (B `f0b41f2`, `6de7bc4`)。
- 路径参数含非 ASCII 时框架不一定自动 decode — 日文 handle 原样传 API 查无此物 404, 显式 decodeURIComponent (B `61ce46e`, `9787480`)。
- auth middleware 的 matcher 要排除健检/静态资源, 否则监控探针全被踢去登录 (B `699505e`)。
- 分页游标的排序参数必须 SSR 与客户端一致, 不一致 = cursor 错位、加载更多返回空 (B `86b43a5`)。

### 2.7 埋点与分析 (均项目 B)

- 离页前发事件用 event_callback + event_timeout 兜底, 不用 setTimeout 猜时长; transport beacon 与 event_callback 互斥, 二选一 (B `22026e6`, `11a35f2`)。
- 全量交互自动追踪 = 事件洪水, 配额内挤掉关键业务事件, 后果是整批删除 — 埋点从一开始就白名单化 (B `042092e`)。
- 测试/内部流量用 tester_id 归因链隔离; 关掉自动 page_view 后要手动补发, 否则漏斗断头 (B `42e3f32`, `d7e1ae6`)。
- 埋点 useEffect 依赖数组多挂一个状态 = 事件重复发送 (pageview 依赖 auth 态在登录变化时重发) — 每个事件独立 effect, 只挂真正触发源 (B `5540ac9`)。

## 3. 后端与数据

### 3.1 数据建模

- **字典/主档引用存 id, 不存名字文本** — 按名 join 是一整类 bug 的根 (同名撞 key/跨域并集/脏数据无法消歧), 每个消费点都要重复消歧逻辑。改造存量用"加 id 列 + 名字双写兼容", 老读方零改动。
- 可推导的状态别落字段 — 锁定判定做派生查询 (SQL 一次查得), 存字段必有不同步窗口 (`12d68d2`; B `07af188` 同结论: 删字段只留推导函数)。
- 审计链/校准历史类实体用 append-only 仓储: 物理上不提供 update/delete, 改错走"修正条目引用原 ID"; 历史明细 + 主表 summary 双写 (`f1b0bfa`)。
- 合规数据不物理删: 归档 = 标记列 + list 默认排除; 破坏性批量操作先给 dryRun 预览端点 (`ee1232f`)。
- 审计/证据链的显示字段落快照列, 不靠 JOIN 实时取 — 被引用对象删除后链上失名 (`ea54679`)。
- 动态字段拆分用 KV 表而非 N 张 typed 表, 新字段无需 ALTER (`de7f907`)。
- 权限检查粒度与审计记录粒度分离, 两个推导函数各管各的 (`6f58fc7`)。
- 小型从属集合用整体替换语义 (delete+insert / PUT replace), 比 diff 三路 CRUD 简单可靠 (`f6164b5`)。
- 广播型「已读」用单条水位线 (lastSeenAt), 不做 per-user fan-out 表 — 数据结构直接消掉整类同步问题 (B `73d933a`)。
- 排行/统计存原始明细事实表、读取时滚动窗口聚合, 别存预聚合固定周期 — 周单位预聚合在月边界错位, 口径变更也僵化; 同步做日次 upsert + 过期自动删 (B `c5c28ef`)。
- 时间窗聚合的默认期间用「有数据的最近期间」兜底 — 写死"上个月"在数据滞后时空表 (B `5c35219`)。
- 集计管道的有效性双层设防: 写入侧过滤 (集计时剔除无效实体) + 展示侧再过滤 (取不到即剔除) — 上游状态在集计后还会变 (B `0af1584`)。

### 3.2 引用完整性 (无 FK 库的生存法则)

- 删除级联靠显式子表清单维护, 清单漏一张 = 成批孤儿; 新增子表时同步更新级联清单。
- 同一实体的多个删除入口收敛到共用的引用检查 + 级联函数, 各写各的必然漂移 (`2943d3a`)。
- 级联漏表靠"想起来"修必复发 — 每次修复要「历史孤儿清零 + 修后回归零」双验证。
- "静默宽容缺失表" (跳过 42P01) 是孤儿数据问题家族的源头 — 宽容要有账 (`42d1573`)。

### 3.3 写路径正确性

- 提交类操作加幂等守卫 (重复提交返回已提交 ID 的明确错误); 不可靠网络的写端点加客户端幂等键 (`928e05c`, `3ff1a91`)。
- 跨实体自动回填四原则: 唯一命中才写 (宁缺毋错)、值全等跳过 (幂等)、失败告警不阻断主流程、冲突走清单确认+字段级留痕; 收敛单一实现挂全部写入方 (`18a2024`)。
- 库存类联动用事务内原子 UPDATE (`SET qty = qty - x`), 不做读-改-写。
- 客户端 for 循环逐条调接口的"批量"改服务端原子端点, 半途失败不留不一致 (`66f8054`)。
- 完整性强校验放在状态转换点 (提交审核), 不放每次保存 — 分次保存流程每存必校会挡住半成品 (`89bbc32`)。
- 编号生成: 定制分支收敛为模板 token 配置表 (`{YYYY}{####}` + 周期重置), SELECT FOR UPDATE 原子取号, 新机制 fallback 双轨兼容 (`ca44ba1`); setval 用 GREATEST(max, last_value) 只进不退。
- 复制实体走白名单: 编号/日期/审计字段一律重新生成 — 照抄登记日期新记录在倒序列表沉底"找不到" (`442393e`)。
- 导入匹配歧义拒写: 同键多条命中一律拒写并计数返回, 不猜 (`f2bf43d`)。
- 日期区间查询上界 +1 天排他 — "今天..今天"按 0 点截断查不到当天 (`1155f3a`); 日期比较按本地日粒度归一, `new Date(str)` 带 UTC 时刻会误判。
- 时区这类横切问题在数据结构层根治 (ORM defaultNow + 会话时区统一), 不追着 53 个调用点打补丁。
- 数据里引入 Unicode 特殊字符 (上下标 ₂/³) 必须配套搜索归一化 (`9a2b3e0`); 中文 query param 必须 URL-encode (`a0a2f29`); query 里含 `:/` 的 ID (gid://) 同样必须 encodeURIComponent (B `85ed23d`)。
- 查询用户/实体用不可变主键, 不用 email 等可变自然键 — 用户改邮箱即断链 (B `7f5e490`)。
- 结构化 ID (GID) 匹配用锚定全串的正则, 子串匹配会命中别的实体类型 (B `b9be9f5`)。
- 多行命中场景禁用无排序 findFirst — 结果非确定; 显式业务优先规则 (findMany + 裁决函数) (B `91c7f69`)。
- 竞态防覆盖用 DB 条件更新 (事务内 `WHERE responseStatus IS NULL`), 派生状态从更新后同一快照算, 不靠前端禁用按钮 (B `6de7bc4`)。
- 破坏性批处理的备份必须内建到**每次执行**且是「移动非拷贝」(只写空目标, 冲突警告+跳过留人裁决), 一次性独立备份步骤是设计缺陷 (B `e0aa005`)。
- sanitize 与长度截断有顺序依赖: 先转义再截断 (转义加字符会超限); 用户上传验 magic bytes 不信扩展名 (B `b5affcd`, `d176ff1`)。

### 3.4 SQL / ORM

- ORM 生成的 SQL 别想当然: 相关子查询列限定可能静默失效 (条件恒真/标量子查询变全表 MIN), 结果错而非报错 — toSQL 实证, 同模式全站扫 (`438fbd5`, `67796b0`)。
- SQL 可移植纪律 (为换库留后路): 禁方言 (ILIKE/::cast/RETURNING/jsonb/ON CONFLICT...), 分页与 ID 生成这类高危点抽单独适配层而不是散落各 repo。
- SQL 模板两处拼同一表达式, 空白不一致会触发 "must appear in GROUP BY", 用 subquery 别名规避 (`61c853c`)。
- 数值精度: JS toFixed/toPrecision 是 round-half-away, 银行家舍入 (round-half-even) 要自己实现; 复刻计算逐公式对老码实证。金额乘除的浮点误差在**边界处**统一 Math.round 收口, 不散落各算式 (B `77d1366`)。

### 3.5 ETL / 迁移

- 简化/砍表要建立在看过真实数据之上; 0 行不证伪 (可能是模板库), 配置表有无数据才是启用信号; 基于备份库的"0 行不迁"结论, 生产迁移日逐条重新对账。
- ETL 列映射按物理列名, 不匹配要报错不许静默丢 (`64e665a`); 带显式 ID 的导入工具内建序列校准 (setval), 一次性校准治标 (`d3f1717`)。
- 回填类 ETL 用 COALESCE 只补 NULL 不覆盖手工值; 一次性平移建标记表防二次执行; 存量修复宁缺勿错 — 唯一命中才升格, 歧义留 NULL 出清单 (`3aa6f1b`, `2060e33`)。
- 迁移保留源系统的拼写错误和真实 ID (FK 才能对上); 不"顺手增强"业务规则 — 便利功能可能违反原系统约束被整批撤回 (`21dd957`, `cdecf5e`)。
- 大规模自动转换必须有机器可验证的验收标准 (1021 张表 DDL 转换靠内存库全量 parse 兜底); regex 转换先 stash 引号内容防误伤 (`ebe2060`)。
- 层级数据遍历必须带 visited 防环 — 真实老数据里就有环 (`e34d6f1`)。
- 大表 ETL 分批 insert (万行级单条 INSERT 爆栈)。
- 客户端持久化缓存 (IndexedDB) 会掩盖 schema 漂移 — INSERT 一律显式列名 + 客户端库要有自动补列迁移 (`821d3fe`)。
- 数据管道迁移三步走: 新表并行稼働 → 消费方切换 → 删旧表旧批处理 (含 DROP migration), 不留双轨长驻; 删旧机制时全局扫参照点 — admin 面板还挂着已删 service (B `c5c28ef`→`db19eaf`, `d53a7f1`)。
- 外部同步表 (Airbyte 类) 的迁移与应用 ORM 迁移物理分离, 别让 ORM diff 把同步表当漂移删掉 (B `caae85d`)。

### 3.6 运维与依赖

- 一切 DDL 走迁移文件, 手工 raw ALTER 必产生环境漂移 (本地改了 schema 没记账 → 生产 500) (`10e7de6`); schema 声明 ≠ DB 列存在, 缺列让子查询把整个列表打成 500 (`eb13324`)。
- 看不到日志/无法直连的生产环境要内建自诊断通道: 迁移状态端点 + probe 探针回传真实 SQL 错误 + 启动自动迁移记账 (`08b0dec`)。
- 选第三方库先查 license 与 npm 供应链状态 (商业闭源/停更带漏洞排除); 复用仓库已有依赖不新引同类库; 新依赖确认进 lockfile, 否则 npm ci 直接死 (`30ee76b`, `ee771d4`)。
- SDK 默认端点 ≠ 你的租户区域 — 国际/中国工作区要显式配置 Domain, 默认值只对默认区生效 (B `bfea4b9`)。
- JWT 滑动续期可以完全 server-driven: 响应头推新 token, 客户端零状态零定时器 (`844a94e`)。
- 新窗口/打印渲染用 DOM API + textContent, innerHTML 拼用户输入就是 XSS 面 (`f54ce53`); 必须 dangerouslySetInnerHTML 的场景 (CMS 富文本) 先过 DOMPurify (B `4939965`)。

### 3.7 外部 API 集成 (均项目 B)

- 分页取外部数据源必须把过滤+排序下推到服务端 (view/filter), 客户端过滤 = 关键数据被翻页截断静默丢失 (666→190 条) (B `269ad76`, `7d1d7d8`)。
- 「未找到」与「取得失败」是两种错误, 禁 catch-and-return-null 折叠; 把任意 404 当"无数据"会掩蔽路由缺失/部署不整合 — 只认响应体里的结构化错误标识 (B `ffb2eda`, `816d7ec`)。
- 同一语义错误的多种表现形 (HTTP 401 / GraphQL ACCESS_DENIED) 归一成同一异常类型, 否则 token refresh 只认一种入口; token 消费点逐个接 refresh, 漏接的点表现为"数据全空/全掩码"而非报错 (B `76e5117`, `23fee3f`)。
- 外部系统对象 id 会因删除重建而更换 — 引用侧备自然键 (handle) 兜底恢复; 与"字典引用存 id"互补: 外部 id 不受控时需自然键 fallback (B `ef7db8e`)。
- 分块批量外呼要 chunk 级 try/catch 隔离 — 任一 chunk throw 会把已收集的部分结果整体丢弃 (B `6c56f09`)。
- 外部 API 循环调用显式限速; 外呼一律 AbortController 超时防挂起 (B `3607075`, `3a35bfa`)。
- GraphQL 查询字段带权限 scope, 按需最小化 — 多要一个字段就多要一个授权面 (B `9c80df1`)。
- N 次逐条外呼能换 1 次本地 DB 查询就换 — 同步落地过的数据别再去源头逐条问 (B `bb6d6ea`)。

## 4. 安全

- 用户身份一律从 token 派生, 禁止 query/body 传 userID — `?user=` 占位就是 IDOR (`9791149`)。
- 两步"上传→提交"流程, 第二步必须校验第一步产物的所有权 (fileID 属于当前用户); 自增 ID 可枚举的下载端点加 owner-or-admin 守卫 (`8352d84`, `31780b9`)。
- 任何用户数据进 CSV/Excel 导出必须防公式注入: 首字符 `= + - @ TAB CR` 加引号中和, 含用户自定义列头 (`a6370fd`)。
- **鉴权对称性检查**是有效审查手段: 新端点漏 requireAuth 而兄弟路由全有 (`7f5e394`); 看似无害但消耗序列资源的端点也要 auth, 无守卫的取号端点可被刷爆 (`b8a313d`)。
- 注册型横切机制 (按 path 推权限/级联清单/label 映射) 要配"新增时 checklist", 忘登记就误拦或漏防。
- 上线前审计打包项: token 缺 claim 使守卫恒空 (权限静默塌缩)、生产缺 SECRET 启动 fatal、错误消息客户端通用化细节进日志、停用账号 403→401 防枚举、登录时旧弱 hash 透明重哈希升级 (`c372d25`)。
- 安全审查报告结合系统权限模型裁决: 与"全员共享协作"设计冲突的 IDOR 报告做最小修复 (存在性校验防野 ID 写入) + 注释文档化设计选择, 不盲从 (`2780253`)。
- 别用假凭据"探测"登录端点 — 那就是一次失败登录, 会触发锁定连锁 (账号锁→失败计数→限流→测试全红像"限流问题"); 探测健康用不计失败的端点。
- **Cookie 存在 ≠ 会话有效**: middleware 只查 cookie 存在时, 伪 cookie 能直呼 admin action — 每个 server action / 渲染守卫内自行 validateSession (DB 照合) + 授权; admin 页对无权者返回 404 隐藏存在性 (B `6de7bc4`, `6b69c69`)。
- 所有权检验要在状态检验**之前** (先 404 后 403 防 IDOR 信息泄露); 服务端强制「当前状态允许的动作/回答集合」, 不信客户端送来的值 (B `6de7bc4`)。
- 金额/授权判定 fail-closed: 用允许列表 (PAID 状态白名单), null/未知/过期一律倒向保守侧; 价格/掩码取得失败显示锁而不是 ¥0 裸奔; 服务端与客户端同一基准 (B `6de7bc4`, `5f7cdbc`)。
- 横切掩码机制既会漏套也会误套: 新展示面漏套 = 数据泄露 + 点击报错, 对语义不匹配的数据源误套 = 全员不可见 — 新增展示面/数据源都过一遍掩码清单 (B `716e4e3`, `601c7f0`)。
- OAuth 登出要双向核对: 只清本地 cookie, 点登录 IdP 会话又把人自动送进来 (要 redirect 到 IdP logout + post_logout_redirect_uri); 反过来 IdP 的 logout 行为不可信时, 以本地销毁 + `prompt='login'` 强制再认证兜底; logout 跳转 URL 走白名单防 open-redirect (B `3a92bfa`, `0736f47`, `8e44fed`)。
- 内部 API client 的 path 参数拒绝绝对/协议相对 URL、一律经 baseUrl 解析 — 否则 Basic Auth 凭据可被引到任意主机 (B `3a35bfa`)。
- 日志与异常 message 是 PII 泄漏面: URL 中身份段打码, 上游响应体不整段入日志、只留有无+长度元数据 (B `97b9062`)。
- 前端应用不直连分析库/数据仓, 经中台 API 隔离凭据与 PII (B `57da989`)。
- 环境变量拼进 SQL 标识符 (schema 名等) 必须白名单校验, 配置注入即 SQL 注入 (B `77d1366`)。
- 客户端"已同意"标志把条款版本号编进存储 key — 版本更新自然触发全员再同意, 零迁移逻辑 (B `af282ce`, `861208d`)。
- 部署白名单 (Server Actions allowedOrigins) 是新域名上线 checklist 项: 反代后必须配置; 生产域漏登记 = 全部写操作报 origin 错; 弃用域及时摘除 (B `80e327b`, `7262020`, `3d9dd5a`)。

## 5. 测试

### 5.1 断言的质量

- **写完必须读回比对值, 不能只断言状态码** — select 投影 60 列但 map 一列没返回的回归, 界面全空白数据其实落库了, "只测 204"永远抓不到。
- 多字段表单 e2e 用"API 逐字段回读"范式, 专治"收集了但不发送" (`48a66ba`)。
- 断言别硬编码环境事实: 登录人身份 (换临时账号跑整片误报 `e1bc4be`)、时区偏移 (JST 机器 0-1 点必挂)、编号位数 (流水号破百即碎)、干净库计数 (用 ≥ 或自造 fixture `fdffc8e`) — 预期值与造数/会话同源。
- 无 ORDER BY 的查询是间歇性红的经典根因 — 快照类测试先保证生成侧确定性 (`78e7690`)。
- 批量操作的语义先实证再写测试 — "批量下达"实为盖章非建行, 按字面猜必挂 (`ac4da2c`)。
- 超时失败的快照是"后态", 会误导排障; 加页内 fetch 对照探针定位真挂点 (`ac4da2c`)。
- 不造假测试: 功能本体不存在的用例挂账"先产品后测试", 不测项写书面理由进 spec; 挂账/覆盖总账会过时, 执行时逐项重验前提 (`6cc4cfa`)。
- "断言锁现状 (含已知缺陷) → 修复后翻转断言"的 gap 记账工作流 (`bba9e74`); 数据质量事故转常驻护栏断言 (`7eab467`)。反向失败面: 修 bug 前先查旧测试有没有把 bug 锁成了规格 — 旧 e2e 断言"排行不掩码", 修复代码反被 CI 打回 (B `d7b0608`)。
- **空集让断言 vacuously true** — 无数据时默默通过的测试什么都没测; 先断言样本存在, 数据不足显式 test.skip 标注环境原因; e2e 动态探索测试目标 (从导航找有数据的页), 找不到优雅 skip, 不硬编码存量数据 (B `0f03139`, `da74756`, `883295f`)。
- 跨页一致性可写成 invariant 断言 (列表能看价 → 点进详情不 AccessDenied); 响应式回归用多视口 e2e (桌面/移动/断点边界), 核心不变式"无横向滚动"; 滚动/动画类断言先 waitForFunction 等 effect 完成 (B `d7b0608`, `846fd1f`, `da74756`)。

### 5.2 测试数据纪律

- 收尾**硬删** — 产品 DELETE 往往是软删, 列表过滤让残渣不可见, 无声累积 (曾积到 1416 条)。
- 测试一律用带前缀的临时账号, 不用真实账号 — 清理脚本守卫拒清真实账号名下数据导致静默残留; 临时账号连审计日志、角色链一起删净。
- 测试数据绝不进生产; 生产只做只读探测和幂等迁移。
- 清理脚本与产品 schema 同步演进: 新增业务表时"清理清单"是与"级联清单"并列的第二本账; 白名单规则化生成不手工维护 (`5109d68`); 删文件行 `DELETE...RETURNING path` 连带删磁盘散件 (`7c51d3f`)。
- 危险清理脚本内置三重闸门 (非 localhost 拒绝/真实账号拒绝/显式开关) (`ed69bad`); 人工排障造数也走前缀纪律并纳白名单, 规则锚前缀非子串 (`7cf8b34`); 测试指纹不一定在编号上, 自动编号实体标在 memo (`89b5eb2`); 合规禁止硬删的表书面记例外 (`532af5a`); 残留溯源用"操作人+日期"指纹。
- 测试收尾总要手清某类孤儿 = 产品缺级联的气味, 修产品不修测试 (`f671161`)。
- spec 不依赖库里存量数据, fixture 一律自造 (`9f9b69d`); seed/演示数据满字段造数, 空白才可见为 bug (`99dee04`)。
- 随机后缀空间要够大 — 3 位十进制必撞生日, 用时间戳+随机。

### 5.3 flaky 治理与并行

- 并行竞态三板斧: KPI 断言改"重取 API + reload 收敛"; "+1"断言基线紧贴各自造数 (隔 5 个往返会被并行邻居污染); 会变异全局状态的功能不进并行池 (`d7809bf`)。
- 限流/锁定类测试用随机键隔离 + 同刻正对照 (`d0f7e45`)。
- 测试框架硬超时会跳过 finally, 清理不能只靠 finally; e2e 改全局配置先快照 + trap EXIT 兜底复原 (`a875a5e`)。
- 测试工具的"静默容错"分支定期排查 — 必然失败被吞 = 假绿 (`f671161`)。
- 底层语义修正后, 靠巧合通过的测试种子会延迟爆雷 — 修语义时全链检索同语义种子同步 (`e74ecd3`)。
- 全屏 backdrop 弹窗 (公告 modal) 遮断点击是 e2e flake 源, 测试前置「有则关闭」helper (B `3cb6386`)。
- "上次为什么过了"可能是水合竞态的假阳性; trailingSlash 环境下 DOM href 被规范化加尾斜杠, 精确匹配 selector 失效 (B `9bf8763`)。

### 5.4 基建与选择器

- API 契约测试 (smoke) 抓不住 UI 回归, 必须配 e2e; 改动涉及的 UI 流没 spec 就补。
- 共享测试 helper 是单点: 页面改版 11/11 全红正是防线生效的形态, 修一处即全绿 — 优于选择器散落各 spec (`6611555`)。
- 测试基建的假设会过期 (写死端口/seed 工厂没跟上 auth 演进), 假设跟主干一起演进 (`bc557d8`)。
- 存活扫描的路由清单从注册真源生成, 手列必有盲区 (60→131 条) (`f559ec1`)。
- 给筛选 Select 补 aria-label: 无障碍与 e2e 定位双赢 (placeholder 是 span 定位不到) (`b6aa095`)。
- SPA hash 跳转断言用 expect.poll(page.url()) 不用 waitForURL; 瞬态 query 参数 (挂载即清) 不进断言 (`48a66ba`)。
- 虚拟列表下拉选人/选批次一律先键入过滤再选 — 残留数据把下拉撑长后目标掉出渲染窗。
- 跑法三要素文档化成铁律 (起跑目录/env 凭据/前置账号), 跑前 lsof 确认服务活着。
- 保留式跑法 (KEEP_DATA 开关) 要连 globalTeardown 一起早退, 漏一层留的数据就被清掉 (`b7a85ab`)。
- smoke 套件模块化: 单模块可独跑 <30s, 服务停时优雅 skip (`438f5bf`); 仓库无测试框架时配轻量断言脚本, 不为一个任务引入框架 (`5dcc91c`)。
- macOS bash 3.2: `check "$(cmd "带转义JSON")"` 嵌套会撕碎 body — 先赋值变量再断言。
- 批量 regex codemod 后必须人工审计兜底 — 跨行 JSX 匹配不到, 报"全部完成"实则漏网 (`b55aa17`)。
- networkidle 在有 SSE/长连接的页面必然超时, e2e 等待一律用 selector/content waits (B `d9fa440`)。
- Playwright strict mode 多命中用 .first()/更精确定位显式表达意图, 别靠碰运气的单命中 (B `3189f4f`)。
- 功能域给独立测试入口 (make target/单模块命令), 改哪块跑哪块, 全量套件太慢会让人跳过测试 (B `e3b1353`)。

## 6. 流程 / 协作

### 6.1 范围与考古 (移植/对照类工作)

- 一切以老 UI 正推范围/命名/操作习惯, 不拿"已迁了什么"倒推收编 — 倒推法的盲区 = 没迁过的都看不见。
- 考古警惕死壳: "有按钮 ≠ 有功能" (Visible=False/handler 注释)、"有 Modal ≠ 有实现"、整目录 frm 可能是空壳真实现在别处; 死按钮可静态排查 (Button 无 onClick/htmlType/href) (`d0cd24c`)。
- 排期前逐项实证防伪需求: 手册/文档推测的功能先 grep 源码确认存在; "太重缓做"的判断也要实证 — 原判"7 表矩阵设计器"实际只是两列+简单 SP (`e3c2121`, `e5d09ec`)。
- 老文案可能走运行时多语言表, Designer 里的 .Text 只是占位; **"查不到"必须如实说"查不到", 不能升级成"不存在"** (`78e7690`)。
- 配置真源在 DB 不在源码时, 只认权威证据 (截图/导出), 绝不按名字猜归属 — 猜错整体撤回 (`8e8a39b`)。
- 别信字段名暗示的语义 (frequencyMonths 实际存天数), 拿真实数据实证 (`c683453`); UTF-16 文件 grep 无声失效用 rg。
- 老系统某层是硬编码就照抄硬编码, 不发明新配置机制 (`9c8dcc2`); 移植不擅自升级状态机, 老实现一个 flag 就照搬两态 (`cf85b4d`)。
- 门控依赖的数据映射不存在时不做假门控 — 假安全比没有更糟, 诚实记 gap (`513d0d1`)。
- 撤除误判功能要全链删净 (tab/路由/schema/表/smoke/e2e) 并顺手补级联清单 (`dfb3f19`)。
- 调查结论沉淀成需求文档 (REQ-*.md), 写明证据来源 — 不落地就重复调查重复犯错; 由实现反推文档的过程本身是审计, 常顺带揪出真 bug (`1634a35`)。
- 有意偏离老系统/规范的每处决策存档 + 注释"非漏实现", 防被后人当 bug 修回 (`f39979e`)。
- 依赖未迁移/无落点时「降级 + 书面记录」, 不硬造关联不造假数据; 落地条件记录在案 (`43bbd52`)。
- 移植参考实现时按目标仓的流儀转译 (全局 CSS/命名/i18n 体系), 基盘不存在的依赖 (feature flag、通知机制) 显式记录见送り理由, 不硬造 (B `6de7bc4`, `d176ff1`)。

### 6.2 修复与审计

- **修任何 bug 前先全局 grep 同类模式, 一起修**; 报告"全站 N 处, 修 M 处, 豁免原因"; 能抽共享组件就不每处手搓。
- 大规模审计"发现与修复分离": 先出总清单再统一裁决分批修; 疑点分 真修/误报/已在位 三类 — 误报写防误修注释, 已在位补断言锁定 (`cd40e0a`, `1e1680b`)。
- 修不能复现的 bug 做防御性兜底并如实标注"未能复现待确认", 不假装根治 (`76807a2`)。
- 注释不阻复发 — 同一教训注释记过两次第三次照样犯; 结构性防护 (测试/audit 脚本/hook) 才阻 (`1e5bbd4`)。
- 反复出现的规范违规固化成可 grep 的 audit 脚本 + 行内豁免注释机制; grep 不到的标 [人审项] 进 review checklist — 诚实区分机器能守的和只能人守的 (`17d3632`)。
- 横切修复 (70+ 处同类) 先文档化工程决策再机械扫; 脚本改代码防把 import 插进多行 import 中间 (`ccf0309`)。
- "欠账注释"定期重审 — 依赖到位后理由过时壳还挂着 (`3870122`)。
- 控制台也算 UI: dogfood 时 deprecation 警告清零作验收项 (`1c24d43`)。
- **功能可达性是上线验收项**: 功能实现在某页但站内没有任何导线指向它 = 等于没做, 会被整体 revert; 移设到用户真实动线才复活 (B `e85ac25`, `2c470bb`)。同一详情弹窗有多个入口时每个入口都要接线, 只接一处就是移植漏 (B `6de7bc4`)。
- 生产疑难先加**显式的一次性诊断日志 commit** (记录照合中间态), 定位根因后显式撤除, 不在 UI 层来回翻转显示逻辑; 根治手段是换可靠数据源, 不是调显示守卫; "功能没出来"的常见根因是环境配置缺失 (B `680dc1b`, `046d411`, `6647f44`, `d700bc0`)。

### 6.3 任务拆解与执行 (spec/plan/SDD)

- spec 里"新表该挂哪张老表"这类断言, 派发前先验证真实数据流 (哪个 repo 真的在写那张表), 不凭字面想当然。
- 跨任务边界的需求最容易丢: "全部完成时回填父表"活在任务边界之间, N 次任务级 review 都过但没人实现 — 收尾整体 review 不可省。
- 退役/删除共享资源前, 独立确认它没被范围外功能共用 — "看起来同一功能"的表可能是另一个活功能的存储层。
- 并行派活显式分配资源 (编号/文件名/fixture), 两个 agent 各自"取下一个号"必撞。
- 完工后回头勾掉**所有**记录该活的账本 (TODO+REQ 双账本), 否则下个会话把完成的活当 pending 重做 (`330c17d`)。
- 补列类任务先"确定整体" (老窗体全列盘点含隐藏列) 再逐项实现; 注意实体 1:n 关系, 不把子表压成文本列。

### 6.4 架构演进路径

- 原型期 YAGNI: dark mode/主题切换/骨架屏整批重写后又整批删除; 原型期直接上成熟组件库, 手写控件全是沉没成本 (`331d774`, `6651144`)。
- mock→真后端分层策略: repo 抽象层 + 字段映射集中一处 + 单实体"三件套 PoC" (fetch 封装/同签名 repo/handler skeleton) 验证通路 (`caeb400`)。
- schema/seed 与 UI 改动分层分 commit — UI 被整批回退时 schema 因独立无损全部保留 (`3db8acb`)。
- "先读后写"落地顺序: 只读视图复用现有端点先覆盖 80% 诉求, 写流程等业务明确 — 零新 endpoint 先交付价值 (`f19b968`)。
- 通用基建 (调度器/文件服务/导出/ID 生成器) 建一次全站复用, 新需求桥接已有基建 (`f31523b`); 新端点实现前先查既有端点是否已覆盖。
- 多格式输出 (PDF/XLS、打印面/录入面) 共用同一份渲染真源/列定义常量, 消灭双取数漂移 (`c7d90c7`)。
- 生态内已有成熟服务就不在应用内自建重依赖层 — PDF 从内置渲染库+CJK 字体切到既有 Lambda, 切换后内部实现连字体资产整层删净; 外部集成改走中台后, 直连通道的 OAuth/限流/缓存/重试整层删除不留 fallback (B `2a7601c`→`a40d585`, `02a4de6`, `e05366f`)。

### 6.5 仓库卫生与 CI

- 一个工作区绝不许两套 git 双重跟踪 — 外层与内嵌仓库各记了不同会话的提交, 靠 subtree split 抢救; 定死"唯一提交处" (`a946583`)。
- 新增顶层目录后 `git check-ignore` 验证 — 历史 ignore 规则会无声吞掉整个新目录源码 (`9b805ae`)。
- 引用旧 commit 哈希前先 `git cat-file -t` 验证存在 (前会话可能实际没提交)。
- repo 根 ≠ 项目根时, husky hooksPath / lint-staged 的工作目录要显式对齐, 否则 hook 静默不跑 (B `39b62f5`); 冗余嵌套路径 (repo/frontend/frontend 类) 尽早理顺, 拖越久参照点越多 (B `36912c3`)。
- lint & typecheck 作部署前置 gate, 不只做本地建议 (B `c246f9f`); CI 的 OIDC 会话时长按最慢步骤预留, 默认时长在长构建里中途过期 (B `6c1174a`); secret 命名对齐既有环境的既成惯例, 别发明新名 (B `3be68b0`)。

## 7. 元经验

最有效的工作闭环:

> **踩坑 → 根因写进 commit 正文 → 泛化成"纪律" (可 grep 的配方 / hook / 脚本 / 白名单 / 共享组件) → 全站扫一遍存量 → 派活时写进 brief。**

坑不可怕, 同一个坑踩第二次才可怕 — 而防第二次靠的全是**机制** (audit 脚本、purge 守卫、useSubmitLock、typecheck 命令统一、级联清单), 没有一条是靠"下次注意"。

用户的每条反馈都值得问一句: **这是个例还是一类?** 是一类就固化成约定 + 机械检查 — 这是整套经验里复利最高的一条。

项目 B (完全不同的技术栈与业务域) 独立复现了同一批规律: 同一个 IME 输入 bug 几周后在另一处重打一遍 (没全局 grep)、大爆炸式 UI 改动当天被整体 revert (没小步)、无导线的功能整体被撤 (没验收可达性)、"数据源不可靠"靠调显示逻辑拉锯多轮最后还是换数据源根治。跨项目双重印证: 这些不是某个项目的特殊性, 是工程重力。
